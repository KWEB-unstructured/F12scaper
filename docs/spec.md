# 기획 요약 (개발자 도구 방탈출 기획서 기준)

## 컨셉
- **F12 이스케이프**: 개발자 도구 기능 하나가 방 하나인 웹 방탈출. "페이지는 거짓말을 하고, 정답은 F12 안에 있다"
- 대상: 웹 개발을 막 배우는 대학생 (1차), 퍼즐을 좋아하는 개발자·스터디 운영자 (2차)
- PC 크롬 권장 (엣지 지원), 플레이 30~60분, 8단계

## 스토리
(2026-11-10 수정안, 형씨 제안 · 셋 합의. 원안의 "운영체제"는 "보안 시스템"으로 이름을 바꿨다)

학교 도서관에서 과제를 하던 주인공은 우연히 접속한 수상한 웹사이트 **"THE ARCHIVE"** 에 갇힌다. 웹사이트 안에서 탈출 방법을 찾던 중, 자신이 단순한 오류로 갇힌 것이 아니라 누군가에게 납치당했다는 사실을 알게 된다.

등장인물
- **나 (플레이어)**: 학교 도서관에서 과제를 하다가 수상한 웹사이트에 접속하고, 그 안에 갇힌 학생. 웹사이트 곳곳에 남겨진 단서를 찾아 탈출하려 한다.
- **브라우저 (안내자)**: 웹사이트 안에서 주인공을 안내하는 조력자. 사이트의 구조와 숨겨진 기능을 알고 있으며 탈출에 필요한 힌트를 준다. 하지만 모든 것을 알려 주지는 않는다. 단계 대사와 힌트는 이 캐릭터의 말로 준다.
- **보안 시스템**: 웹사이트 내부 시스템을 관리하는 존재. 주인공을 비인가 접근(이상한 프로세스)으로 보고 차단·삭제하려 한다. 시스템 알림·경고 톤으로 등장하고, **오답 반응을 맡는다** (예: "비인가 접근 감지 (2회)").
- **거미 (Spider)**: 웹사이트 곳곳을 돌아다니며 정보를 수집하는 크롤러. 주인공의 행동을 감시하고 흔적을 추적한다. 지금은 **콘솔 로그로 가끔 흔적만 보인다** (예: `[crawler] visited: /archive`). 정체와 납치범 세력과의 관계는 미정.
- **납치범 세력**: 수상한 웹사이트를 운영하며 사람들을 유인하고 납치하는 집단. 목적 미정. 아직 직접 등장하지 않는다.
- **UNKNOWN USER**: 콘솔로 말을 거는 정체불명의 접속자 (먼저 갇힌 사람으로 보임). 프롤로그 끝에서 1단계 단서 쪽을 가리킨다.

이름·대사·진행률 라벨은 코드가 아니라 데이터 파일([src/content/](../src/content/))에서만 바꾼다. 스토리가 아직 바뀌는 중이기 때문이다.

주요 사건
1. 주인공은 학교 도서관에서 과제를 하다가 우연히 수상한 웹사이트에 접속한다.
2. 접속한 순간 화면이 이상하게 변하고, 주인공은 웹사이트 밖으로 나갈 수 없게 된다.
3. 웹사이트 내부를 탐색하며 각종 퍼즐과 미션을 해결한다.
4. 탐색 중에 자신 말고도 웹사이트에 갇힌 사람들이 있었다는 흔적을 발견한다.
5. 웹사이트를 관리하는 존재와 자신을 추적하는 거미의 정체를 알아 가면서, 배후에 납치범 세력이 있다는 사실에 다가간다.

결말: 미정

진행 방식
- 단계마다 브라우저 대사 → 퍼즐 → 단서 획득 → 보안 시스템 알림 순서.
- 진행률은 임시로 **"탈출 진행률"** 로 표시한다 (0% → 100%).
- 실제 학교·기관 이름, 로고, 실제 사이트 화면은 쓰지 않는다. 가짜 주소는 예약 도메인(`.example`, `.invalid`)만 쓴다.

### 프롤로그 (3~5분, "미연시 → 모니터 속으로 빨려 들어감")
도서관에서는 사이트가 모니터 안에 있다가, 이상 현상이 생기면 모니터가 화면 전체로 커지면서 사이트가 세상 전체가 된다(= 갇힘).

| 장면 | 내용 |
|---|---|
| library | 1인칭 도서관 배경 + 하단 대사창 내레이션 ("오후 5:42" …). 끝나면 모니터로 줌인 |
| monitor | 모니터 속 가짜 브라우저·검색창. 무엇을 치든 과제 문장으로 한 글자씩 바뀐다. 검색 결과에 THE ARCHIVE |
| archive | 평범해 보이는 사이트 (Welcome / Archive / Community / About Us). 날짜가 이상하고 없는 페이지가 있다. 메뉴를 몇 개 본 뒤 "열람하기" |
| glitch | 화면이 깨지고 `WELCOME BACK.` … `Connection status: Restricted`. 모니터가 화면 전체로 커진다 |
| trapped | "화면에 표시되는 정보가 전부라고 생각하십니까?" → "개발자 도구를 확인하세요." F12 를 누르면 콘솔 메시지가 이어지고 1단계로 |

- 프롤로그 안에서 플레이어가 스스로 F12 를 누르게 하는 게 목표다. 별도 "F12 여는 법" 안내는 없다 (30초 동안 반응이 없으면 커서 근처에 작은 안내만).
- 이름은 프롤로그 전에 받고(도서관 PC 로그인), **기록은 프롤로그가 끝난 뒤 1단계부터 잰다.**
- 갇힌 뒤 새로고침하면 도서관으로 돌아가지 않고 "도망칠 수 없습니다" 연출 뒤 복귀. 뒤로 가기는 막는 척하며 보안 시스템 경고. 창 닫기는 막지 않는다.

아직 정하지 않은 것 (정하면 이 목록에서 지우고 위에 반영한다)
- 결말과 8단계에서 밝혀지는 정체 (8단계·클리어 화면 작업 전까지)
- 진행률 표시의 최종 이름 (지금은 임시 "탈출 진행률")
- 콘솔의 `[ SYSTEM ]` 화자가 보안 시스템인지 납치범 쪽인지
- 분위기 (가벼운 탈출 게임 / 긴장감 있는 스릴러)
- 8단계 퍼즐의 "관리자 패널" 표현을 새 스토리에 맞출지

## 단계
| 단계 | 구간 | 기능 | 퍼즐 | 정답을 얻는 방법 | 난이도 |
|---|---|---|---|---|---|
| 1 | 튜토리얼 | Elements (주석) | "개발자는 늘 흔적을 남긴다" 문구만 보인다 | HTML 주석 안의 비밀번호 | ★ |
| 2 | 튜토리얼 | Elements + Styles | "다음" 버튼이 없다 | `display: none` 을 지워 숨은 버튼을 보이게 함 | ★ |
| 3 | 튜토리얼 | Console | 콘솔에 `unlock()` 함수가 남아 있다는 로그 | 페이지 제목에 숨은 열쇠로 `unlock("열쇠")` 실행 (입력창 없이 자동 통과) | ★★ |
| 4 | 본게임 | Application (쿠키) | "권한이 없습니다" 화면 | 쿠키 `role=student` 를 `admin` 으로 바꾸고 새로고침 | ★★ |
| 5 | 본게임 | Network | 버튼을 누르면 "실패"만 뜬다 | 실패한 요청의 응답 본문과 헤더에서 단서를 읽음 | ★★★ |
| 6 | 본게임 | 기기 모드 (반응형) | "작은 화면으로만 보인다" 힌트 | 화면 너비 375px 에서만 보이는 문장 | ★★★ |
| 7 | 보스 | Sources (중단점) | 정답이 화면에 0.1초만 깜빡인다 | 중단점을 걸어 변수에 담긴 값을 잡음 | ★★★★ |
| 8 | 최종 | 종합 | 관리자 패널의 마지막 자물쇠 | 1~7단계 조각을 규칙에 맞게 조합 | ★★★ |

난이도 원칙
1. 튜토리얼(1~3)에서는 어느 탭을 열지 안내자가 직접 알려 준다.
2. 본게임(4~6)부터는 어느 기능을 쓸지 스스로 추리하게 한다.
3. 보스(7)는 컴공 학생도 고민하게 하되, 힌트 3개를 다 쓰면 누구나 풀 수 있어야 한다.
4. 최종(8)은 새 기능 없이 지금까지 모은 것을 정리하는 보상 단계.

## 게임 시스템
- **정답 검증**: 1~7단계는 정답 해시만 클라이언트에 두고 비교. 8단계는 서버가 검증하고 기록을 남긴다.
- **오답**: 보안 시스템 경고 "비인가 접근 감지 (n회)". 같은 단계에서 5회 틀리면 브라우저가 첫 힌트를 권한다 (차단은 없으므로 "/5" 같은 상한은 표시하지 않는다).
- **힌트**: 1 방향만 (+3분) · 2 열어야 할 탭과 위치 (+5분) · 3 거의 정답 (+10분). 감점은 클리어 시간에 더해진다.
- **기록** = 실제 클리어 시간(서버가 기록한 시작 시각 기준) + 힌트 패널티. 단계별 소요 시간도 기록.
- **진행 저장**: localStorage. 4단계가 쿠키를 퍼즐로 쓰므로 쿠키에 저장하지 않는다. "처음부터 다시"로 전체 초기화.
- **랭킹**: 닉네임, 최종 기록, 힌트 수. 로그인 없음. 힌트 0개 배지, 비속어 닉네임 필터, 비현실적으로 짧은 기록 제외.
- **클리어 화면**: 최종 기록·순위·단계별 시간, "오늘 사용한 개발자 도구 기능 7개" 카드(실무 활용 한 줄씩), 이미지 카드 저장·링크 공유.

## 화면 (7개)
시작 → (PC?) → 로그인(닉네임) → 프롤로그 → 단계 화면(1~8) → 클리어 → 랭킹. 모바일이면 모바일 안내.

| 화면 | 주요 요소 |
|---|---|
| 시작 | 게임 제목, 시작 버튼, 윤리 안내 문구, 크롬 권장 표시 |
| 모바일 안내 | PC 접속 안내, 링크 복사 버튼 |
| 로그인 | 닉네임 입력 ("도서관 PC 로그인"으로 연출) |
| 프롤로그 | library → monitor → archive → glitch → trapped (위 "프롤로그" 참고). 대사창, F12 유도, 콘솔 메시지 |
| 단계 | 브라우저 대사, 퍼즐 영역, 정답 입력창(터미널 스타일), 힌트 버튼(힌트도 브라우저가 말함), 보안 시스템 경고, 타이머, 탈출 진행률(임시 이름) |
| 클리어 | 최종 기록, 단계별 소요 시간, 개발자 도구 기능 카드, 공유 버튼 |
| 랭킹 | 순위표, 내 순위, 힌트 0개 배지 |

윤리 안내 문구: "이 게임의 모든 퍼즐은 이 페이지 안에서만 이루어집니다. 권한 없이 다른 사이트의 쿠키나 요청을 조작하는 것은 불법이 될 수 있습니다." (시작·클리어 화면)

## 범위
- MVP: 8단계, 정답 검증, 3단 힌트, 타이머, 진행 저장, 랭킹, 클리어 화면, 모바일 안내
- 확장 1차: 기록 카드 이미지 공유, 힌트 0개 배지, 영어 지원
- 확장 2차: 시즌제, 사용자 제작 퍼즐, 교육용 해설 모드

## 테스트·성공 지표
- 개발자 도구 초보 3명 + 컴공 학생 3명. 설명 없이 지켜보며 막히는 단계와 시간을 기록.
- 한 단계에서 10분 이상 막히면 힌트 수정, 1분 안에 풀리면 퍼즐 강화.
- 크롬·엣지·광고 차단 확장 환경 확인.
- 목표: 클리어율 6명 중 5명 이상, 평균 30~60분, 단계별 최장 체류 10분 이내.
