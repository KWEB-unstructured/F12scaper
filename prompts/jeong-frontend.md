# 정씨 (프론트·UI 리드) — Claude Code 작업 프롬프트

**쓰는 법**: 레포 루트에서 Claude Code 를 열고, 해당 주차의 코드 블록을 통째로 붙여 넣는다.
CLAUDE.md 는 자동으로 읽히므로 규칙은 다시 설명하지 않아도 된다.
작업 전에 브랜치를 만든다: `git switch -c 정씨/<작업명>`

담당 파일: `index.html`, `src/styles/`, `src/screens/`, `src/stages/stage1.js` `stage2.js` `stage6.js`

---

## 1주차 — 화면 시안, 공통 레이아웃, 시작·인트로 화면, 1·2단계

```
나는 이 프로젝트에서 프론트·UI 담당(정씨)이야. 이번 주 목표는 화면 시안과 공통 레이아웃, 시작·인트로 화면, 1·2단계 퍼즐이야.

먼저 읽어 줘: CLAUDE.md, docs/spec.md(화면 구성·단계 표), docs/contracts.md(단계 모듈 형식), src/main.js, src/screens/start.js, src/screens/intro.js, src/stages/stage1.js, src/styles/base.css

할 일
1. 공통 디자인: src/styles/base.css 의 임시 스타일을 "가상의 호랑이대학교 전산실 서버 콘솔" 분위기로 다시 잡아 줘.
   - CSS 변수(:root)로 색·간격·글꼴을 정리하고, 화면 공통 레이아웃(.screen)을 만든다.
   - 실제 학교 로고·색·포털 디자인을 흉내 내지 않는다.
   - 프레임워크·Tailwind·CSS 라이브러리 금지. 웹폰트를 쓰면 1개까지만.
2. 시작 화면(src/screens/start.js): 게임 제목, 시작 버튼, 윤리 안내 문구, "크롬 권장" 표시. 문구는 src/content/story.js 것을 쓴다(문구 자체는 형씨 담당이니 바꾸지 말고 필요하면 TODO 로 남겨).
3. 인트로 화면(src/screens/intro.js): 상황 설명 대사를 한 줄씩 보여 주는 연출, 닉네임 입력, F12 여는 법 안내. /api/start 호출과 createProgress 흐름은 그대로 유지한다.
4. 1단계(src/stages/stage1.js): 지금 예시 구조는 유지하고 퍼즐 화면만 다듬어 줘. 주석은 Elements 탭에서 퍼즐 영역을 펼치면 바로 보이는 위치에 둔다.
5. 2단계(src/stages/stage2.js): "다음" 버튼이 없는 화면. 버튼은 인라인 style="display: none" 으로 숨기고(hidden 속성·Tailwind 클래스 금지), 플레이어가 Styles 에서 지우면 버튼이 나타나 정답(조각)을 보여 주게 한다.
   - 정답은 아직 확정 전이니 임시 정답 test2 를 유지하고, 확정되면 `npm run hash -- "정답"` 으로 answerHash 만 바꾼다.
   - 힌트 3개(방향 → 탭과 위치 → 거의 정답)와 선배 조교 대사 초안도 써 줘. 형씨가 나중에 다듬는다.
   - 버튼을 화면 밖으로 빼는 식의 꼼수는 쓰지 말고, "display: none 을 지운다" 한 동작으로 풀리게 해.

완료 기준
- npm run dev 로 시작 → 인트로 → 1단계 → 2단계까지 직접 진행된다.
- 1·2단계를 개발자 도구를 처음 쓰는 사람이 힌트 2개 안에 풀 수 있는지 스스로 점검하고, 걸리는 점을 알려 줘.
- npm run build 가 통과한다.
- src/core/, api/, 다른 사람 단계 파일은 수정하지 않는다. 꼭 필요하면 멈추고 나한테 먼저 물어봐.
```

## 2주차 — 단계 화면 UI(입력창, 힌트 버튼, 타이머), 6단계

```
나는 프론트·UI 담당(정씨)이야. 이번 주는 단계 화면 UI와 6단계야.

먼저 읽어 줘: CLAUDE.md, docs/contracts.md, src/screens/stage.js, src/core/game.js(읽기만), src/stages/stage6.js, src/styles/stages.css

할 일
1. 단계 화면(src/screens/stage.js) UI 다듬기
   - 화면 하단 터미널 스타일 정답 입력창: 프롬프트(root@horangi:~$), 깜빡이는 커서 느낌, 오답이면 짧게 흔들리는 효과, 정답이면 "ACCESS GRANTED" 같은 전환 연출 후 다음 단계로.
   - 상단: 단계 번호·제목, 서버 복구율 진행 바(0→100%), 타이머(힌트 패널티 포함 시간 + 패널티가 붙었다는 표시).
   - 힌트: confirm() 대신 직접 만든 모달로 "힌트 N을 열면 +M분" 을 확인받는다. 연 힌트는 선배 조교 말풍선으로 보여 준다.
   - 유령 관리자 도발 메시지 영역을 눈에 띄게 만든다.
   - 진행 규칙(정답 확인, 힌트 카운트, 감점 계산, 단계 전환)은 src/core/game.js 의 함수만 호출한다. 규칙을 화면 코드에서 다시 계산하지 마.
   - 대사·힌트는 textContent 로만 넣는다 (힌트에 <!-- --> 같은 문자열이 있음).
   - 3단계처럼 stage.input === false 인 단계에서는 입력창이 숨는지 확인한다.
2. 6단계(src/stages/stage6.js): "작은 화면으로만 보인다" 힌트가 있는 화면. 너비 375px 이하에서만 보이는 문장에 조각을 숨긴다.
   - 미디어 쿼리는 src/styles/stages.css 의 6단계 구역에 둔다.
   - 크롬 기기 모드에서 iPhone SE(375px) 등으로 맞췄을 때 보여야 한다. 창 크기를 줄이는 것만으로도 풀릴 수 있다는 점은 괜찮다.
   - 기기 모드에서 새로고침해도 모바일 안내 화면으로 튕기지 않는지 확인한다 (src/main.js 참고).
   - 임시 정답 test6 유지, 힌트 3개·대사 초안 작성.

완료 기준
- 1~8단계를 임시 정답(test1~test8)으로 끝까지 진행할 때 UI 가 깨지지 않는다. 3단계는 콘솔에서 unlock("test3").
- 폭 1280px 과 375px(6단계) 모두에서 레이아웃을 확인했다.
- npm run build 통과. 담당 외 파일은 수정하지 않는다.
```

## 3주차 — 클리어·랭킹 화면, 모바일 안내, 기록 카드

```
나는 프론트·UI 담당(정씨)이야. 이번 주는 클리어 화면, 랭킹 화면, 모바일 안내, 기록 카드야.

먼저 읽어 줘: CLAUDE.md, docs/spec.md(게임 시스템·화면 구성), docs/contracts.md(API 응답 형식), src/screens/clear.js, src/screens/ranking.js, src/screens/mobile.js

할 일
1. 클리어 화면(src/screens/clear.js)
   - 최종 기록, 순위(rank 가 null 이면 "집계 제외" 안내), 사용한 힌트 수, 단계별 소요 시간 막대.
   - "오늘 사용한 개발자 도구 기능 7개" 카드: 각 stage 모듈의 tool/toolUsage 를 쓴다(문구는 각 단계 담당이 채움).
   - 윤리 안내 문구, 랭킹 보기, 처음부터 다시 버튼.
2. 기록 카드: 클리어 기록을 이미지(PNG)로 저장하는 버튼과 링크 공유 버튼(navigator.share 가 없으면 클립보드 복사).
   - 이미지는 라이브러리 없이 <canvas> 로 직접 그리는 방식을 먼저 시도하고, 너무 복잡하면 html-to-image 를 쓰자고 나한테 제안해 줘.
3. 랭킹 화면(src/screens/ranking.js): 순위표, 내 순위 강조, 힌트 0개 클리어 배지. API 실패·빈 목록 상태 처리.
4. 모바일 안내(src/screens/mobile.js): PC 접속 안내, 링크 복사 버튼과 복사 완료 피드백. 375px 화면에서 보기 좋게.

완료 기준
- API 가 mock 일 때(.env.local 없음)와 김씨가 붙인 실제 API 일 때 모두 화면이 동작한다.
- 모바일 UA(크롬 기기 모드 + 진행 중인 게임 없음)로 첫 접속하면 모바일 안내가 뜬다.
- npm run build 통과. 담당 외 파일은 수정하지 않는다.
```

추가 점검
